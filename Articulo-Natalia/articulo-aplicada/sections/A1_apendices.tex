\section{Ejemplo de evento de detección enviado por el microservicio}
\label{ap:evento_kafka}

El Listado~\ref{lst:evento_kafka} muestra un ejemplo simplificado del mensaje
JSON que el microservicio de visión envía al tópico de detecciones en Apache
Kafka. Este formato se utiliza como contrato de integración entre la capa de
visión y el backend de gestión.

\begin{lstlisting}[language=json,caption={Ejemplo de evento de detección publicado en Kafka.},label={lst:evento_kafka}]
{
  "eventId": "b3a9f1c0-4f8a-4f1b-9d93-8b0c1f5a1234",
  "plate": "ABC123",
  "confidence": 0.92,
  "cameraId": "CAM-ENTRADA-01",
  "parkingId": 1,
  "timestampUtc": "2025-05-12T15:43:21Z",
  "trackId": 37,
  "eventType": "DETECTION",
  "imageMeta": {
    "frameIndex": 1542,
    "resolution": "1280x720"
  }
}
\end{lstlisting}

En el backend, un componente consumidor de Kafka interpreta este mensaje,
verifica la validez de la matrícula, determina si corresponde al inicio o a
la actualización de una visita, y actualiza la base de datos en consecuencia.

\section{Configuración básica de la fuente de video con \textit{IP Webcam}}
\label{ap:ip_webcam}

Como se describe en la Sección~\ref{sec:resultados}, las pruebas del
prototipo se realizaron utilizando un teléfono móvil Android con la
aplicación \textit{IP Webcam} como fuente de video, emulando el comportamiento
de una cámara IP. A continuación se resumen los pasos básicos seguidos para
la configuración, con el fin de que otros grupos puedan reproducir el
montaje experimental:

\begin{enumerate}
    \item Instalar la aplicación \textit{IP Webcam} desde la tienda oficial de aplicaciones del dispositivo.
    \item Conectar el teléfono y el servidor donde se ejecuta el microservicio de visión a la misma red local (por ejemplo, una red Wi-Fi institucional).
    \item En \textit{IP Webcam}, configurar la resolución de video y la orientación de la cámara según el escenario de prueba (entrada de parqueadero, distancia aproximada al vehículo, etc.).
    \item Iniciar el servidor de video en la aplicación y anotar la URL generada (por ejemplo, \texttt{http://\textit{IP\_DEL\_TELEFONO}:8080/video}).
    \item Registrar dicha URL en el módulo de configuración de cámaras del sistema ANPR-VISION, de manera que el microservicio de visión consuma este flujo igual que consumiría el de una cámara IP dedicada.
\end{enumerate}

Desde el punto de vista de la arquitectura, esta configuración no requiere
cambios en el código del microservicio: la diferencia entre una cámara IP
física y el teléfono con \textit{IP Webcam} se limita a la dirección y a los
parámetros de la fuente de video. Esto permite validar el sistema en contextos
educativos sin necesidad de adquirir cámaras especializadas.

\section{Notas sobre reproducción del entorno de despliegue}
\label{ap:reproduccion_entorno}

Para facilitar la reproducción del entorno de despliegue utilizado en el
proyecto, se elaboraron archivos \texttt{docker-compose} específicos para los
entornos de desarrollo, QA, \textit{staging} y producción. Aunque los
archivos completos se omiten aquí por extensión, su estructura general es la
siguiente:

\begin{itemize}
    \item Definición de servicios para el backend .NET, el portal web Angular y la base de datos relacional.
    \item Definición opcional de servicios para Apache Kafka, su coordinador (cuando aplica) y el microservicio de visión.
    \item Configuración de redes internas (por ejemplo, \texttt{anpr-net-develop}, \texttt{anpr-net-prod}) para aislar los servicios por entorno.
    \item Uso de ficheros \texttt{.env} por entorno para gestionar credenciales, cadenas de conexión y parámetros específicos (URLs de cámaras, tópicos de Kafka, claves de JWT, etc.).
\end{itemize}

La combinación de estos archivos con las canalizaciones de Jenkins descritas
en el cuerpo del artículo permite reconstruir el entorno con un esfuerzo
moderado, constituyendo un recurso útil para futuras cohortes que deseen
utilizar ANPR-VISION como base para nuevas actividades académicas o
investigaciones aplicadas.
